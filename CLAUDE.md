# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bilingual (English + Arabic) marketing site for **Bonyan** — an engineering consultancy / construction firm in Muscat, Oman. Single premium homepage (8 sections) plus lightweight About, Services, and Contact pages. Built with TanStack Start and originally scaffolded in Lovable.

## Commands

```sh
npm ci          # install exact deps from package-lock.json (npm is authoritative, not bun)
npm run dev     # Vite dev server with HMR; regenerates src/routeTree.gen.ts
npm run build   # production SSR bundle — also the only "typecheck"; run before every handoff
npm run build:dev
npm run preview # serve the built app
npm run lint    # ESLint + Prettier check (prettier violations fail lint)
npm run format  # apply Prettier
```

No test framework is configured. Verify changes by running `npm run lint` and `npm run build`, then manually checking affected `/en/*` and `/*` (Arabic) routes at mobile and desktop widths, including RTL.

## Architecture

### Localization is URL-driven and route-triplicated

There is **no locale state or context**. Locale is a pure function of the pathname (`localeFromPath` in `src/i18n/index.ts`): `/en` or `/en/...` → English; **everything else, including `/`, → Arabic**. English lives under `/en`; Arabic is served from both bare paths (`/`, `/about`) and `/ar/*`.

Each page component is rendered by **three route files** that differ only in `createFileRoute` path and the `locale`/`seo` passed to `seoMeta`:

- `src/routes/index.tsx`, `about.tsx`, `services.tsx`, `contact.tsx` — bare (Arabic)
- `src/routes/en.*` — English
- `src/routes/ar.*` — Arabic

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on dev/build but **is committed** — never hand-edit it; let dev/build regenerate it after adding routes.

### Using translations in components

`useT()` (from `@/i18n`) is the single access point. It returns:

- `t` — the dictionary for the current locale
- `locale` (`"en" | "ar"`), `dir` (`"ltr" | "rtl"`)
- `lp(path)` — builds a locale-aware href (prefixes `/en` for English, leaves Arabic bare). Always route internal links through `lp()`.

All user-facing copy lives in **`src/i18n/en.ts`** (source of truth; exports the `Dict` type) and **`src/i18n/ar.ts`** (`export const ar: Dict = ...`). The two must stay structurally identical — adding, renaming, or removing a key requires editing both files or the build fails. Do not put raw strings in components.

Locale-invariant contact data (phone, WhatsApp, email, map URLs) is the `CONTACT` constant in `src/i18n/index.ts`, **not** the dictionaries.

`seoMeta()` in route `head()` pulls titles/descriptions from `dictionaries.<locale>.seo.*`. `<html lang dir>` is set in `RootShell` in `src/routes/__root.tsx`.

### Component layers (`src/components/`)

- `ui/` — shadcn/ui primitives (new-york style, lucide icons). Generated; avoid heavy edits.
- `site/` — app building blocks:
  - `SiteLayout.tsx` — page shell: `Header` + `main` + `Footer` + `MobileBottomNav`
  - `ui.tsx` — shared primitives: `Btn` (variants + RTL-aware `arrow`), `Reveal` (IntersectionObserver scroll reveal), `SectionLabel`, `GhostNumber`
  - `L.tsx` — `L`, a `<Link>` wrapper that accepts a runtime-built string path; use it (not `<Link>`) for `lp()` paths
  - `assets.ts` — the central image registry (`IMAGES`, `SERVICE_IMAGES`, `PORTFOLIO_IMAGES`, `CLIENT_AVATARS`). Swap an image here to change it everywhere.
  - `Header.tsx` `useNavItems()`, `Footer.tsx`, `MobileBottomNav.tsx` — the three nav lists; update all three together.
- `site/sections/` — the eight homepage sections, composed by `site/pages/HomePage.tsx`
- `site/pages/` — full page compositions consumed by the route files

### Adding a page

1. New component in `src/components/site/pages/`
2. Three route files: `foo.tsx`, `en.foo.tsx`, `ar.foo.tsx` (copy an existing triplet)
3. Dictionary keys in **both** `en.ts` and `ar.ts` (including a `seo.foo` block)
4. Nav entries in `useNavItems` (`Header.tsx`), `Footer.tsx`, and `MobileBottomNav.tsx` as appropriate
5. Run `npm run dev` or `npm run build` to regenerate `routeTree.gen.ts`

### Styling

Tailwind CSS **v4**, configured CSS-first in `src/styles.css` via `@theme inline` — there is no `tailwind.config`. All colors are oklch **semantic tokens** (`bg-background`, `text-primary`, `border-border`, and the light-band set `ivory` / `ink` / `ink-muted` / `ivory-border`). Never hardcode colors.

RTL is handled with logical utilities (`ps-`/`pe-`/`ms-`/`me-`/`start-`/`end-`) and `rtl:` variants (e.g. arrows use `rtl:rotate-180`). Custom `@utility`s: `container-site`, `eyebrow`, `reveal`/`reveal-in`. Custom animation utilities: `animate-float-slow`, `animate-ambient-pulse`, `animate-frame-glow`, `shimmer-button`, plus `.status-ping` and `.trust-dots`. All motion respects `prefers-reduced-motion`.

### SSR & error handling

`src/server.ts` is a custom SSR entry (wired through `vite.config.ts` `tanstackStart.server.entry`) that converts catastrophic 500s and h3-swallowed errors into a static HTML error page. `src/start.ts` registers error + CSRF middleware. `src/lib/lovable-error-reporting.ts` and `error-capture.ts` report client/SSR errors. Leave these alone unless the task is specifically about them. Build target is Cloudflare (nitro) via `@lovable.dev/vite-tanstack-config`.

## Conventions

- Prettier-enforced (fails `lint`): 2-space indent, double quotes, semicolons, trailing commas.
- TypeScript strict; import from `src` with the `@/` alias.
- PascalCase for components/files; `use*` for hooks.
- Do not create `src/pages/`, `_app`, or `app/layout.tsx` — those are Next/Remix conventions. The only layout is `src/routes/__root.tsx` (keep its `<Outlet />`).
- `no-restricted-imports`: the `server-only` package is banned; use `*.server.ts` naming or `@tanstack/react-start/server-only`.

## Lovable integration

Pushing to `main` syncs back to Lovable. **Do not rewrite pushed history** — no force-push, rebase, amend, or squash of pushed commits. Keep the branch buildable. `.lovable/` holds the project id and the original build plan.
